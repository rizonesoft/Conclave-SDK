# AGENTS.md

Shared instructions for agents working in `Conclave-SDK`. Each agent loads this file alongside its own isolated entrypoint (`GEMINI.md`, `CLAUDE.md`, or `CODEX.md`).

## Purpose

`Conclave-SDK` holds the overlay kits (`kits/base`, `kits/todo`, `kits/reviewer`, `kits/automations`, `kits/laravel`, `kits/wordpress`) that carry every agent skill, rule, subagent, script and template, plus prompts and the stdlib-only CLI `forge.py`, used to bootstrap projects under `R:\GitHub`. The SDK is a template: a project takes a copy once and owns it, and nothing links it back to the SDK. `forge.py` notes what it installed in the project's `.conclave/kits.json` (the SDK commit, each file's kit and a digest of its bytes as installed), a record with no path to the SDK that the project may delete.

## Architecture and Working Rules

- **Zero external dependencies:** All Python scripts (`forge.py` and every script in the kits) use the Python 3 standard library only.
- **Atomic writes:** Every file write in tooling uses a temporary file in the destination directory followed by `os.replace`.
- **Strict agent isolation:** Each kit keeps Antigravity skills in `templates/.agents/`, Claude Code skills in `templates/.claude/` and OpenAI Codex skills in `templates/.codex/`, installed as the same folders in target repos. The kits are the only source. The SDK's own `.agents/`, `.claude/`, `.codex/` and `scripts/` are an installed copy of the `base`, `todo`, `reviewer` and `automations` kits, as are `.conclave/reviewers.toml`, `.conclave/automations/` and the kits' files under `docs/`, because the SDK plans, reviews and schedules its own work with them: change a kit file in the kit, then refresh the copy with `python forge.py self-sync` (a test fails until the two match). The `laravel` and `wordpress` kits are not installed in the SDK itself. `scripts/start-run.ps1` (the launcher of the SDK's own unattended run) is the SDK's own file, in no kit. Default provisioning mode is `isolated` so every target repository is 100% self-contained.
- **Prose and table formatting:** Write one line per paragraph and list item in Markdown. Never use em dashes or en dashes anywhere: prose, code, comments, commit messages and generated files. Keep every Markdown table row at or under 120 characters so table rows never wrap in raw `.md` view, and keep TODO `Deliverable` cells and `## N. <Title>` headings to a short noun phrase of at most 88 characters.
- **TODO contract:** All skills and templates enforce small, single-responsibility sections, short `Deliverable` and section titles (`<= 88` chars), granular five-part micro-steps (`Done when:` and backticked path/symbol per item, `Cheaper substitute:` on UI/write items), logical step commits within sections, and a 100% complete development plan with zero silent drops or unowned SPEC controls.
- **Review:** The SDK reviews its own TODO sections three-pass, under `.conclave/reviewers.toml` (the reviewer kit's template pin): one plan review, one round, one completion review, then reconciliations after gaps, up to the pin's `pass_cap`. A section keeps the pin committed at its plan review's candidate, so a pin change is committed before the next section starts.
- **Imported material:** `global/` (the owner's machine-level rules, hooks and skills for Claude Code and Codex) and `plugins/` (account-bound MCP plugins) were imported byte for byte from two retired repositories. `forge.py` never installs either into a project, and only their two `README.md` files are held to the writing rules above; change an imported file only on purpose, never to satisfy a formatter. The findings files under `docs/reviews/` hold reviewers' replies byte for byte under a digest and are exempt too.
- **Output discipline:** Bound command output and run the quick suite, `python -m unittest discover -s tests`, before committing changes (about a minute: it includes a fresh install that runs a section through every review pass to its stamp). Run the full suite, the same command with `CONCLAVE_FULL_TESTS=1` set, when a change touches the stamp (`lib/todo_graph.py`), the dispatcher or the pin loader, and before a release: it adds the stamp tests and the reviewer kit's own suite, which build git repositories and run a stub reviewer and take several minutes.
