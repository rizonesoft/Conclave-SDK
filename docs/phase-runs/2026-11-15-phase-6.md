## Lessons

- A cleanup that must reach a process tree is designed from the ways a tree escapes, before the first test: a child made before containment, a launcher that exits first, containment that fails, an interrupt in between. Three reconciliations each found the next of these in `toolchain-check.py`; `D04 T01 §3` and `§6` (the LSP client and bridge) reuse the finished shape (start suspended in a job on Windows, a session on POSIX, everything after the start inside one `finally`).
- The pre-commit hook refuses a commit while `docs/reviews/` holds unstaged changes, so a stamp cannot be committed alone while another section's findings file is modified: commit the findings first, or both together with a message that names both.
- A change to `forge.py`'s usage text or kit lists runs `python -m unittest tests.test_forge -k documents -k doctor -k list_kits` before it is committed: one of those tests reads the `doctor` usage line itself, and a `-k` selection chosen for the section's own files misses it. The kit tests of the new kits now assert the same line, so the fast local run catches it.
- Lifting a script into a kit is a review of the script, not a move: the plan review of `D04 T01 §3` found six places where the Laravel client reported a check that never ran as a pass (any `initialize` response taken as success, exit 0 from the JSON branch when every server was missing, git failures read as an empty input). Read the source for what it reports when nothing happened before writing the plan's items.
- A check's answer has three kinds, not two: what is so, what is not, and what could not be told. Both `lsp-diagnostics.py` (`failed`, `partial`) and `compdb-check.py` (`unknown`) were sent back until the third kind had its own status and was never folded into a pass or dropped beside a failure.
- A change to what a kit installs is run against every test that installs that kit, not a `-k` guess: `python -m unittest tests.test_forge -k <kit>` misses the tests that loop over all kits (`kit_fixtures`). When `forge.py` `kit_plan` or `apply_kit` changes, run `python forge.py check-all --only tests` once before the candidate is pushed. Found 2026-11-15: `24423a2` turned main red on one such test.
- A claim about another vendor's program is proven by running that program, once, and written as what was measured: Claude Code, Codex and Antigravity were each driven headless against stub language servers with a marker of their own (`CONCLAVE_LIVE_CLAUDE=1`, `CONCLAVE_LIVE_AGENTS=1`). The check reads the session's event stream or the stub's own log, never the model's summary, which changed from run to run. Where the vendor offers no registration for one run (Antigravity), its own add and remove commands under a test-only name, with the list asserted back as it was, are a reversible step done in the run.
- A fixture that starts a process to prove a recursion is impossible must itself be unable to recurse: the mutation "the wrapper calls the compiler by name" made `test_cc_cache.py`'s stub cache start itself without end in WSL until the system stopped it. The stub now carries a depth of three in its environment. Give every stub that runs what it is handed a bound before the first mutation is tried.
- The completion review checks the record, not the tests: five sections in a row (`D04 T02 §3`, `D04 T01 §5`, `§6`, `D04 T02 §4`, and `§3` of the LSP kit before them) came back with one gap, that the suites, the platforms and the mutations were run and not written down. Before a completion review is dispatched, the gate output (each command, system, candidate and result, and each mutation's outcome) is collected and a `- Evidence:` line is added to the findings file with the round's `- Fixed:` lines.
- The Write tool turns a `\u2014` escape in a file's content into the character itself. A test that needs a dash to look for writes `chr(0x2014)`, and every commit that adds or changes a file runs `python -m unittest tests.test_forge -k no_em_or_en_dashes -k markdown_table` (under a second) before it is made, not only the Markdown check.
