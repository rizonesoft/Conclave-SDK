## Lessons

- A cleanup that must reach a process tree is designed from the ways a tree escapes, before the first test: a child made before containment, a launcher that exits first, containment that fails, an interrupt in between. Three reconciliations each found the next of these in `toolchain-check.py`; `D04 T01 §3` and `§6` (the LSP client and bridge) reuse the finished shape (start suspended in a job on Windows, a session on POSIX, everything after the start inside one `finally`).
- The pre-commit hook refuses a commit while `docs/reviews/` holds unstaged changes, so a stamp cannot be committed alone while another section's findings file is modified: commit the findings first, or both together with a message that names both.
- A change to `forge.py`'s usage text or kit lists runs `python -m unittest tests.test_forge -k documents -k doctor -k list_kits` before it is committed: one of those tests reads the `doctor` usage line itself, and a `-k` selection chosen for the section's own files misses it. The kit tests of the new kits now assert the same line, so the fast local run catches it.
- Lifting a script into a kit is a review of the script, not a move: the plan review of `D04 T01 §3` found six places where the Laravel client reported a check that never ran as a pass (any `initialize` response taken as success, exit 0 from the JSON branch when every server was missing, git failures read as an empty input). Read the source for what it reports when nothing happened before writing the plan's items.
- A check's answer has three kinds, not two: what is so, what is not, and what could not be told. Both `lsp-diagnostics.py` (`failed`, `partial`) and `compdb-check.py` (`unknown`) were sent back until the third kind had its own status and was never folded into a pass or dropped beside a failure.
