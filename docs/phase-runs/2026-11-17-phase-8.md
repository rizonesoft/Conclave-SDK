## Lessons

- A change to forge.py's help text or kit list is read by tests in five files (`test_forge`, `test_lsp_kit`, `test_toolchain_kits`, `test_kit_install`, `test_reviewer_flags`): run every test that calls `--help` before pushing such a change, not only the section's own `-k` selection.
- `review-dispatch.py` takes no pass after a section's reconciliation ends complete, so a red-CI fix found after it cannot join the section's chain: the section stamps at the reconciled candidate, and the fix gets its own review outside the section (a findings file not named for a section) before the stamp cites the green run that includes it.
- The pre-commit hook refuses a commit while `docs/reviews/` has unstaged changes, and a dispatcher pass leaves its findings file changed: stage the findings file with every `todo:` commit after a review pass, and read the commit's hash only after the commit landed (twice this run a `Planned:` or writer note named the commit before the one that held it).
- A change to `.github/workflows/tests.yml` is read by tests in `tests/test_check_all.py` (`RealTable` pins every command): run that whole file before pushing such a change. `59a4427` went out with one of them red.
- GitHub's Windows runner keeps its temp folder under an 8.3 short name; this machine's `R:\temp` has none, so a test that compares paths by spelling passes here and fails there. Before pushing a Windows path test, run it with `TEMP` and `TMP` set to an 8.3 form (`C:\Users\DERICK~1\AppData\Local\Temp` here) to reproduce the runner.
- `WScript.Shell` saves and opens a `.lnk` through the ANSI code page (probed 2026-11-18: a CJK name fails `Save()` and reads back an empty description). Every link a kit writes is saved under an ASCII name and moved, and read through `Shell.Application`; test a link writer with a title outside cp1252.
