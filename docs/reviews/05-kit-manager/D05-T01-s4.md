## adversarial: needs-attention

1. **`extensions/vscode/src/host/repoInit.ts:43`: dangling links bypass the `.git` refusal.** Create an existing `repo/.git`, then a symlink `alias` targeting `repo/.git/not-created-yet`. Select `alias` as the destination. `realpathSync.native(alias)` fails, so `canonical` falls back to the parent and appends the literal `alias`, losing its destination. Both checks accept it. Forge’s non-strict `Path.resolve()` resolves the dangling link, and `provision` creates and installs into `.git/not-created-yet`. Resolve dangling link components or refuse paths whose destination cannot be established safely.

2. **`extensions/vscode/src/host/repoInit.ts:73`: the checked destination is not bound to the destination passed to forge.** Point `alias` at a safe disposable directory, then retarget it to a disposable repository’s `.git` while `deps.python()` is pending at line 83. Forge receives the original alias at line 89 and resolves its new destination, bypassing the refusal. This is reproducible deterministically with an injected Python resolver that retargets the link before returning. The guard needs protection at the write boundary; the earlier canonical check alone does not provide it.

3. **`extensions/vscode/src/host/protectedFiles.ts:56`: protected-directory roots are followed through links.** Make `work/docs` a symlink or junction to an external fixture containing `a.md`. `walk()` immediately calls `readdirSync` on that linked root, then hashes external files as `docs/a.md`. Likewise, linking `.conclave` or `.claude` causes `hash()` to follow linked ancestors because `lstatSync` checks only the final component. An external file change can consequently fail an otherwise unchanged init, and snapshots read outside the project. Check ancestors and traversal roots, not only directory children and final files.

## consistency: needs-attention

4. **`extensions/vscode/test/integration/repoInit.test.ts:44`: teardown fails on Linux/WSL.** On these platforms, `symlinkSync(..., "junction")` creates a symbolic link, but `rmdirSync` does not remove symbolic links and throws `ENOTDIR`. Run the `repoInit` suite under the WSL extension host: teardown fails on the first alias and never reaches temporary-directory cleanup. Use platform-appropriate link removal while retaining the requirement that every link is removed before recursive deletion. Do not replace this with recursive removal of the alias.
