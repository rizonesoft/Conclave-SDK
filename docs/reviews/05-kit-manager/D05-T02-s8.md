## Self-review

- Does it make sense: `stamped_newer` compares a kit's stamp entry date with the running SDK's (`datetime.fromisoformat`); a later date, or an unknown date on either side, is a refusal with both commits and dates named. `apply_kit` refuses it outside a dry run (so `kit` exits 2 and the extension's dry runs still read it); `provision` with `refresh` (`sync`) leaves the kit, lists it in `refused_newer` and refreshes the others. A kit with no stamp entry is never refused, so the SDK's own `sync .` is unaffected.
- Found while building: `provision` read the base kit's result as `kit_results[0]`, which raised `IndexError` when `sync` refused base; it now looks base up by name. The unknown-date test, where every stamped kit is refused, caught it.
- Plan correction: the documentation item named the `adopt-conclave` skill, which `§7` builds; `§7` now carries that micro-step.
- Did it break anything: `python -m unittest discover -s tests` passes except the 22 tests needing the SDK's own `.claude/`; the guard tests pass in WSL.
- Mutation: with both guards removed the three guard tests fail.
