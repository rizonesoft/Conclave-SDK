## Response to round 1

All four hold.

1. Settling before the kill finished: once a cancel or timeout starts killing, the exit callback no longer settles the run; it settles when the tree kill is done. Regression with a kill function that kills at once but reports done 300 ms later: the run must not settle first; settling on the exit callback fails it. (`RunOptions.killer`, `killTree` by default, exists for that test.)
2. Deep trees: each round now follows its `ps` snapshot to the whole tree under the root, however deep, and rounds repeat until one finds nothing new. Regression: a chain 25 processes deep is gone when the cancelled run settles (POSIX checks at that instant, counting a zombie as gone; Windows gets 1 s for `TerminateProcess` to show); one generation per round fails it in WSL.
3. Prototype names: the CLI-to-writer table is a `Map`, so `cli = "constructor"` gives no pin. Regression in `testPin.test.ts`.
4. No `[routes]` table: `singleReviewerPin` returns no pin when the text model refuses the structure, and `ReviewerTester.test` turns anything unforeseen into a `refused` outcome, never a rejected promise. Regression in `testPin.test.ts`.

The record advisory is right: the round 1 self-review shows eventual disappearance of a shallow tree only; the two new tests cover cleanup before settling and full traversal. A failed first version of the chain test left processes running on both platforms; they were stopped, and the test now aborts in `finally`.

Gates: unit 80 OK and 2 skipped (run and testPin tests also pass in WSL); integration 35 passing; lint clean.
