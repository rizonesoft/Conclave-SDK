## Response to round 1

All seven hold.

1. Concurrency: each download uses its own temporary names (`<sha>.<pid>-<random>`), one download per commit is in flight per window (keyed by SHA, so two refs naming one commit share it), and a window that loses the publication race uses the winner's complete entry. Integration test: two windows and an alias ref at once all get the same complete entry, with no temporary file left.
2. Interrupted publication: `.complete` (holding the SHA) and `.used` are written inside the extracted folder before one rename publishes it, so a crash cannot leave a half-published entry; an entry that is not complete is removed and rebuilt, never trusted. Test: a cache entry holding only `.complete` is rebuilt.
3. Case collisions: the extractor refuses names that repeat, exactly or differing only in case. Unit cases for both.
4. Limits before consumption: the download is counted while it streams and refused past 100 MB (`maxDownload`, tested with a tiny limit); the extractor checks the archive's size first and reads members one at a time, stopping at the member and size limits.
5. Late network failures: the SHA body and the tarball stream are inside the `github-offline` handling. Test: a server that sends the headers and drops the connection gets `github-offline`.
6. Usable folders: an SDK folder needs a `forge.py` file and a `kits/` folder (types checked); a fresh archive without them is refused and not cached, and a cache hit needs the marker to name its SHA. Test: a README-only archive is refused.
7. Bundled source: `bundledSource` is a pure function, tested for packaged, development, missing, and a malformed `SDK_COMMIT`.

Gates: unit 9 OK; integration 17 passing; lint clean.
