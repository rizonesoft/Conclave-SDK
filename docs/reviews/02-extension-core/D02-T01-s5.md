## Response to round 1

All seven hold.

1. Planted symlink: on POSIX the shared folder is used only if `lstat` shows a real directory (not a symlink) owned by this account and closed to others; otherwise the process uses a fresh private `conclave-XXXXXX` folder. The candidate itself is still created exclusively, so a planted file name is never followed.
2. Cleanup: creating, writing and closing the candidate are inside the deletion's `try`, and only a file this call created is deleted (an existing name is never touched). Test: a write that throws after creation leaves nothing.
3. Fallback folders: the activation sweep also clears this account's `conclave-XXXXXX` folders (old candidates, then the folder if it is old and empty). Writing the test on Linux found that deleting a file refreshes the folder's age, so the age is now read before sweeping; it passes in WSL.
4. Escapes: the reviewer name is decoded from Python's `repr` (backslash, both quote styles, `\x`, `\u`, `\U`), so a name with a backslash or both quotes reaches its card.
5. Save gating: `canSave` now needs the newest edit's own check to be complete (`settled`), so A, B, back to A keeps Save off until A's new check finishes; a check that fails leaves it off.
6. Accumulation: the flow runs one check at a time and keeps only the newest waiting one, so a slow dispatcher runs at most the running check and the newest. The running check is not killed (the dispatcher's 30 s timeout bounds it); its answer is discarded, which is what design section 1's cancellation is for: no stale result is ever painted.
7. Each of these has a test; the record above lists them.

Gates: unit 66 OK and 2 skipped (the POSIX-only tests, run in WSL); integration passing; lint clean.
