## Response to round 1

All five hold.

1. Restricted Mode: `resolvePython` takes `trusted` and, when false, finds and runs nothing and returns an `untrusted` refusal; the host passes `vscode.workspace.isTrusted` and resolves again on `onDidGrantWorkspaceTrust`. The unit test asserts no `PATH` search and no process, with and without a setting.
2. Timeout: `src/host/run.ts` kills with `SIGKILL` and settles on its own timer, so neither a process ignoring `SIGTERM` nor a descendant holding the output open leaves the promise pending; `run.test.ts` proves it with a Node child that ignores `SIGTERM` (settled after 0.5 s).
3. POSIX: the lookup's predicate is now `runnable`, a regular file that on POSIX has execute permission, so a non-executable `python3` earlier on `PATH` is skipped.
4. Folders: resolution is per workspace folder (`getConfiguration("conclave", folder)`), re-resolved when that folder's setting changes; the integration test sets a folder-level `conclave.pythonPath` and gets that folder's refusal.
5. POSIX setting cases: an absolute path, a bare name found on `PATH`, and a too-old setting refused without discovery.

Gates: `npm test` 22 OK, lint clean, integration 3 passing in VS Code 1.142.0.
