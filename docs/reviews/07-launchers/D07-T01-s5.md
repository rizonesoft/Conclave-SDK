1. **P1, lines 204, 205, 209, 211:** Project ownership uses the supplied path without a canonical distro-qualified identity. Two distros containing `/home/x/demo` receive the same mark and icon key; removing one can delete the other’s files. Conversely, Linux, `wsl$` and `wsl.localhost` spellings of one project produce different identities. Define one identity that includes the distro and preserves Linux path case. Test cross-distro isolation and removal through alternate path spellings.

2. **P1, line 205:** Writing `<Title> (<Label>).lnk` can overwrite another project’s shortcut when titles match, or an unrelated existing shortcut. The description mark protects removal but does not protect replacement. Require an ownership check before replacement, refuse a conflicting destination without changing it, and test two projects with the same title.

3. **P1, lines 205–208, 212, 215:** Reading stored arguments does not prove the agent launches correctly. The tests can pass with broken quoting, incorrect fallback arguments or a wrong working directory. Add windowless execution tests using harmless stand-ins that record the received arguments and working directory, covering Windows and WSL, terminal and fallback forms, paths containing spaces and apostrophes, and both permission settings. Verify that the interactive WSL shell actually exposes a wrapper defined in `.bashrc`.

4. **P2, lines 203–205, 209:** Installation failure handling is unspecified beyond malformed profiles. A corrupt image, failed renderer, denied shortcut save or failed replacement must not leave a broken link or trigger stale-file deletion after a partial installation. Add explicit nonzero exits and diagnostics, temporary-file cleanup, preservation of existing working links, and cleanup only after successful publication. Test renderer failure and a failed replacement with existing shortcuts present.

5. **P2, lines 201–203, 211:** `-Remove` has no explicit independence from profile loading, icon validation or WSL availability. Following the listed sequence can make uninstall fail after an icon disappears, the profile becomes invalid or the distro stops working. Put removal before creation-only validation and test those conditions, including a second removal when nothing remains.

6. **P2, lines 205, 208:** The WSL launch forms provide no persistent error state when WSL cannot start or the agent command fails. A direct `wsl.exe` fallback can close its console before the operator reads the error. Specify a diagnostic that remains visible until acknowledged, and test WSL startup failure and a missing agent command.
