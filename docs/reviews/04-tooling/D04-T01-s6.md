1. **P1, lines 231 and 236: Agent interoperability is unproven.** The registration checkpoint only searches snippets for a filename; the bridge tests use a custom client. Both can pass while Codex or Antigravity cannot discover or call the tools. Require protocol assertions for initialization, capabilities, initialized notifications, tool schemas and result envelopes, plus an actual discovery and tool call through each target agent using the documented registration. See the MCP [lifecycle](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle) and [tool contract](https://modelcontextprotocol.io/specification/2025-06-18/server/tools).

2. **P1, line 231: Failure and empty-result behavior is incomplete.** Position tools have no defined outcome for an unavailable server, unsupported method, timeout or error response; diagnostics do not distinguish an empty table, unsupported file, unanswered diagnostics and a successful clean result. Define these outcomes, bounded waits and fallback to later matching servers. Add multi-server tests with the first server failing or returning empty, plus invalid arguments, outside-project paths, unreadable files and malformed tables. The single successful stub does not prove these paths.

3. **P1, lines 231–232: Diagnostic freshness has no enforceable contract.** The existing client caches diagnostics by URI without retaining their document version. After `didChange`, delayed diagnostics for the previous version can satisfy a naive cache read. Require invalidation and a defined freshness/wait policy, respecting the table’s `settle` setting. Test delayed old diagnostics followed by new diagnostics, an error becoming clean, and a server that never publishes an updated result.

4. **P2, lines 231–232: Persistent startup omits existing configuration behavior.** Program resolution, prerequisite checks and `${scratch}` expansion/cleanup currently live in `run_server`, which also closes the client after each run. Merely using `Client` persistently does not inherit them. Explicitly preserve that startup behavior, including `init`, `settings` and server roots, and test it through the bridge with a rooted server and scratch-bearing preset.

5. **P2, line 234: Removing the cumulative cap does not establish bounded memory.** The existing client retains diagnostics for every published URI and has an unbounded outgoing queue. Dropping late responses and limiting individual messages leaves these accumulators untouched during a long session, particularly when a server stops reading. Specify bounded retention/backpressure or server termination, document any eviction behavior, and test repeated calls against a non-reading server and diagnostics across many documents.

6. **P2, line 235: Shutdown proof omits shutdown during work.** EOF and SIGTERM tests can pass if they only stop an idle bridge. A bridge blocked waiting for diagnostics can miss EOF until the agent forcibly terminates it. Require prompt shutdown during an outstanding request, and test interrupt and exception exits as well as idle EOF, verifying the complete server tree disappears.
