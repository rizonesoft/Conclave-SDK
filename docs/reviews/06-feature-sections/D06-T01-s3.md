## Response to round 1

All five findings are real; fixed in `6fa5df6`.

- Finding 1 (review text fabricating or invalidating rounds): `record` itself had the same blind spot, since it numbers rounds by counting `## Round` lines. Fixed at the writer: `record` writes review lines that begin `## Round` with a Markdown escape (`\## Round`, rendered as the same text), so every `## Round` line is an envelope it wrote and both the numbering and the reader are unambiguous. The 13 rounds already recorded in this repository were checked: none of their reviews has a line beginning `## Round`, so no record needs migrating.
- Finding 2 (malformed metadata truncating silently): the block runs from the heading's blank line to the next blank line, every line must be a well-formed field with a value, Writer and Run exactly once, Effort at most once; anything else makes the file unreadable.
- Finding 3 (lossy UTF-8): strict decoding; a decoding failure names the file in `unreadable`.
- Finding 4 (one bad entry aborting the listing): a per-file `OSError` names the file and the listing continues; a folder that cannot be walked is reported the same way.
- Finding 5 (coverage): `test_review_text_that_looks_like_a_round_is_neither_counted_nor_listed` (a review with `## Round trip serialization` and a fenced fake round; fails with the escape removed) and `test_a_malformed_or_unreadable_record_is_named_and_the_rest_still_listed` (empty Effort, two Writers, no blank line, non-UTF-8, a folder named `*.md`; fails with the old lenient loop).
- Gates: dispatcher tests OK on Windows (skipped=1) and WSL; full suite OK; `--list-rounds` on this repository: 13 rounds in 6 files, none unreadable.

## Response to round 2

All three findings are real. This was the second patch on the same parser, so the approach was re-thought rather than patched (`a7c7388`):

- Findings 1 and 2 (other line breaks; the escape visible in fenced code): escaping is gone. `record` states the review's line count (`- Lines: N`), both sides split lines on `\n` alone (`text_lines`, a CRLF checkout's `\r` dropped), and the reader skips exactly N lines unread, requiring a blank line or the end after them, so a hand edit to the review or the count shows as unreadable. The review is stored byte for byte. Rounds recorded before the count have no Lines field and run to the next round heading, as before; the 14 recorded in this repository read, none unreadable.
- Finding 3 (resolve on a symlink loop): unreadable paths are reported with `os.path.abspath`, never `resolve()`, and a `RuntimeError` from reading a loop is caught with the other read failures.
- Record: the missing-blank fixture was already refused before; the new cases are `test_the_line_count_envelope_holds_against_other_line_breaks_and_hand_edits` (U+2028 and U+0085, a pre-count round, a changed count, an added line) and `test_a_symlink_loop_is_reported_without_aborting_the_listing` (POSIX); with the round trip's verbatim assertions, all three fail against `6fa5df6`.
- Gates: 28 dispatcher tests OK on Windows (skipped=2: the child-process test and the symlink test) and WSL (no skips); full suite OK.

### adversarial: needs-attention

1. `kits/reviewer/templates/scripts/review-dispatch.py:307`: Malformed counts can abort the entire listing. Replace `- Lines: 1` with `- Lines: ²`. `isdigit()` accepts it, but `int()` raises `ValueError`, which `list_rounds()` does not catch. A 4,301-digit decimal also raises on Python’s default conversion limit. Expected: report the file as unreadable and continue listing other files.

2. `kits/reviewer/templates/scripts/review-dispatch.py:317`: A blank line does not establish that the count matches the review. Record `Plain.`, then replace it with `Plain.\n\nExtra review.` without updating `Lines`. The reader accepts the file and silently scans past the extra text. This contradicts the documented promise that a line-count-changing hand edit makes the file unreadable.

### consistency: needs-attention

3. `kits/reviewer/templates/scripts/review-dispatch.py:330`: Review text is not stored byte for byte. `text_lines()` removes carriage returns before the writer rejoins the review, so recording `A\r\nB` stores `A\nB` on WSL. Additionally, line 324 uses universal-newline reading when appending: record `A\rB`, then append another round. The first record initially parses, but appending converts its embedded carriage return into another LF without updating its count; the resulting file is unreadable. Newline normalization must not alter the counted payload.

### integration: needs-attention

4. `kits/reviewer/templates/scripts/review-dispatch.py:329`: Accepted model text can break the envelope. A TOML model value containing a trailing newline, such as `"gpt-6-astra\n"`, passes `MODEL.match()` at line 80 because `$` permits a final newline. If the reviewer returns successfully, `record()` places that newline inside the heading and the reader rejects the resulting record. The validation defect predates this commit, but remains an end-to-end exception to the requested model-text guarantee.

### record: needs-attention

5. `kits/reviewer/templates/scripts/review-dispatch.py:328`: The fallback numbering counts quoted review headings again. Record one review containing `## Round 9: none`, then make its metadata unreadable by changing `- Effort: medium` to `- Effort:`. Appending the next actual round returns **3**, not **2**, because the fallback regex counts the unescaped payload heading. This becomes possible with the redesign’s removal of escaping.
